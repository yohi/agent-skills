# DocSync Verifier (整合性検証官 — 利用ガイド)

マルチエージェントレビューパイプライン（Phase 1: Gemini 指摘 → Phase 2: DocSync Verifier による裏取り）において、仕様書・設計書・表・Mermaid図などのドキュメント間整合性を厳密に検証するためのスキルです。
エージェント向け指示は [SKILL.md](SKILL.md) を参照してください。

---

## 1. パイプラインにおける役割と設計思想

### 🔴 コード非参照（Code Blindness）ルール
* 本スキルは **ソースコード（`.ts`, `.py`, `.go` 等）を一切参照しません**。
* 「コード側で正しく実装されているから問題ない」という推論を禁止し、**「ドキュメント単体で矛盾なく成立しているか」** だけを評価します。

### 🔴 証拠に基づく3段階判定
1. **✅ 承認 (TRUE)**: 指摘された矛盾がドキュメント間に実在する。
2. **❌ 却下 (FALSE)**: 誤検知（定義に準拠している、または記述が一致している）。
3. **⚠️ 要確認 (AMBIGUOUS)**: ドキュメント上の情報が不足しており、人間の仕様決定が必要。

---

## 2. 人間による入力フォーマット例

エージェントに検証を依頼する際は、以下のように `<review_results>` ブロック（または Markdown 表）で指摘事項を渡します。

```markdown
以下のレビュー指摘の整合性を検証してください。

<review_results>
| Issue ID | Source（元仕様） | Target（検証対象） | 指摘内容 |
|---|---|---|---|
| ISS-001 | specs/auth.md §2.1 | docs/api.md L45 | セッション有効期限が specs では 30分 だが api.md では 60m と記載されている |
</review_results>
```
